# macOS Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Mission Centre PostgreSQL as a relocatable, ad-hoc-signed `MissionCentrePg.app` for Apple Silicon, without regressing the Linux build.

**Architecture:** The application has no system-introspection layer, so no application logic changes. Three code-level changes — drop an unused libdbus dependency, add a pure `bundle_root` function, and set GTK's environment variables in-process from the executable's own location — plus a standalone bundling script that relocates the Homebrew GTK stack into `Contents/Frameworks`. No launcher shell script and no `cfg(target_os)` guards in `src/`.

**Tech Stack:** Rust (edition 2021), GTK4 + libadwaita, meson/ninja driving Cargo, Homebrew for the macOS toolchain, `dylibbundler` for dylib relocation.

**Spec:** `docs/superpowers/specs/2026-07-24-macos-port-design.md`

## Global Constraints

- **Architecture:** arm64 (Apple Silicon) only. No universal2, no Intel.
- **`LSMinimumSystemVersion`:** `15.0`.
- **Bundle and schema identity:** `io.github.paulsnow.MissionCentrePg` — `CFBundleIdentifier` must equal the GSettings schema ID.
- **Version strings:** `0.0.0` throughout (`CFBundleShortVersionString`, `CFBundleVersion`).
- **Author:** Paul Snow. **Licence:** GPL-3.0-or-later; every new source file carries the same GPL header block as existing files in `src/`.
- **No `cfg(target_os)` in `src/`.** Platform behaviour is decided at runtime, so the same code compiles everywhere.
- **The Linux build must not regress.** Meson changes are guarded by `host_machine.system()`.
- **Spelling:** British English in all prose, comments and documentation.
- **Signing is ad-hoc only** (`codesign --sign -`). No Developer ID, no notarisation, no DMG.
- **Commit messages:** conventional-commit prefixes, no co-author or attribution trailers.

**Tasks 1–4 are verifiable on Linux. Tasks 5–8 require an Apple Silicon Mac** running macOS 15 with the prerequisites of Task 5 installed.

```rust
/// The directories a bundled build resolves relative to its own executable.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct BundlePaths {
    /// Holds `mission-centre-pg.gresource`.
    pub resource_dir: PathBuf,
    /// `GSETTINGS_SCHEMA_DIR`.
    pub schema_dir: PathBuf,
    /// `XDG_DATA_DIRS`, so GTK finds the bundled icon theme.
    pub data_dir: PathBuf,
    /// `GDK_PIXBUF_MODULEDIR`.
    pub pixbuf_module_dir: PathBuf,
    /// `GDK_PIXBUF_MODULE_FILE`.
    pub pixbuf_module_file: PathBuf,
}

/// Returns the `.app` root when `exe_path` sits at
/// `<root>/Contents/MacOS/<binary>`, and `None` anywhere else — which is
/// every path on Linux.
pub fn bundle_root(exe_path: &Path) -> Option<PathBuf> {
    let macos_dir = exe_path.parent()?;
    if macos_dir.file_name()? != "MacOS" {
        return None;
    }

    let contents_dir = macos_dir.parent()?;
    if contents_dir.file_name()? != "Contents" {
        return None;
    }

    Some(contents_dir.parent()?.to_path_buf())
}

/// Where each bundled resource lives, given a bundle root. The layout here
/// and the layout written by `support/create-macos-bundle.sh` must agree.
pub fn bundle_paths(root: &Path) -> BundlePaths {
    let resources = root.join("Contents").join("Resources");
    let pixbuf = resources.join("lib").join("gdk-pixbuf-2.0").join("2.10.0");

    BundlePaths {
        schema_dir: resources.join("glib-2.0").join("schemas"),
        data_dir: resources.join("share"),
        pixbuf_module_dir: pixbuf.join("loaders"),
        pixbuf_module_file: pixbuf.join("loaders.cache"),
        resource_dir: resources,
    }
}
```

mod application;

use std::path::PathBuf;

use gtk::prelude::*;
use gtk::{gio, glib};

use application::MissionCentrePgApplication;
use mission_centre_pg::platform::{bundle_paths, bundle_root};

/// Points GTK at the schemas, icon theme and pixbuf loaders carried inside a
/// macOS `.app`, and returns the directory holding the gresource. `None` when
/// not running from a bundle, which is always the case on Linux.
///
/// Must run before any glib call and while the process is still
/// single-threaded: GLib reads these variables lazily on first use, and
/// `set_var` is only sound before threads exist. This crate is edition 2021,
/// where `set_var` is safe; moving to edition 2024 makes it `unsafe` and this
/// function is where that will bite.
fn configure_bundle() -> Option<PathBuf> {
    let exe = std::env::current_exe().ok()?;
    let paths = bundle_paths(&bundle_root(&exe)?);

    std::env::set_var("GSETTINGS_SCHEMA_DIR", &paths.schema_dir);
    std::env::set_var("XDG_DATA_DIRS", &paths.data_dir);
    std::env::set_var("GDK_PIXBUF_MODULEDIR", &paths.pixbuf_module_dir);
    std::env::set_var("GDK_PIXBUF_MODULE_FILE", &paths.pixbuf_module_file);

    Some(paths.resource_dir)
}

fn main() -> glib::ExitCode {
    let bundled_resource_dir = configure_bundle();

    // An explicit MCPG_RESOURCE_DIR always wins: development builds run from
    // the build directory and depend on it.
    let resource_dir = std::env::var("MCPG_RESOURCE_DIR").unwrap_or_else(|_| {
        bundled_resource_dir
            .unwrap_or_else(|| PathBuf::from("/usr/share/mission-centre-pg"))
            .to_string_lossy()
            .into_owned()
    });
    let resource_path = format!("{resource_dir}/mission-centre-pg.gresource");

    let resources = gio::Resource::load(&resource_path)
        .unwrap_or_else(|e| panic!("Failed to load resources from {resource_path}: {e}"));
    gio::resources_register(&resources);

    MissionCentrePgApplication::new().run()
}
```

# meson build. See docs/superpowers/specs/2026-07-24-macos-port-design.md.
#

set -eu

SOURCE_ROOT="${1:?usage: create-macos-bundle.sh <source-root> <build-root>}"
BUILD_ROOT="${2:?usage: create-macos-bundle.sh <source-root> <build-root>}"

APP_ID="io.github.paulsnow.MissionCentrePg"

MACOS_DIR="$CONTENTS/MacOS"

[ "$(uname -s)" = "Darwin" ] || { echo "this script only runs on macOS" >&2; exit 1; }
[ "$(uname -m)" = "arm64" ] || { echo "Apple Silicon only; see the spec" >&2; exit 1; }

for tool in brew dylibbundler rsvg-convert iconutil glib-compile-schemas \
            gdk-pixbuf-query-loaders gtk4-update-icon-cache codesign otool; do
    command -v "$tool" >/dev/null 2>&1 || { echo "missing required tool: $tool" >&2; exit 1; }
done

BREW="$(brew --prefix)"
GTK_PREFIX="$(brew --prefix gtk4)"
ADW_PREFIX="$(brew --prefix libadwaita)"
ICON_PREFIX="$(brew --prefix adwaita-icon-theme)"
HICOLOR_PREFIX="$(brew --prefix hicolor-icon-theme)"
RSVG_PREFIX="$(brew --prefix librsvg)"

[ -f "$SVG" ] || { echo "no icon at $SVG" >&2; exit 1; }

mkdir -p "$MACOS_DIR" "$FRAMEWORKS" "$RES/glib-2.0/schemas" "$RES/share/icons" "$LOADER_DIR"

cat > "$CONTENTS/Info.plist" <<PLIST

    <key>CFBundleDisplayName</key><string>Mission Centre PostgreSQL</string>
    <key>CFBundleExecutable</key><string>mission-centre-pg</string>
    <key>CFBundleIconFile</key><string>MissionCentrePg</string>
    <key>CFBundlePackageType</key><string>APPL</string>
    <key>CFBundleShortVersionString</key><string>0.0.0</string>
    <key>CFBundleVersion</key><string>0.0.0</string>
    <key>LSMinimumSystemVersion</key><string>15.0</string>
    <key>LSApplicationCategoryType</key><string>public.app-category.developer-tools</string>
    <key>NSHighResolutionCapable</key><true/>
</dict>
</plist>
PLIST

ICONSET="$BUILD_ROOT/MissionCentrePg.iconset"
rm -rf "$ICONSET"
mkdir -p "$ICONSET"
for size in 16 32 128 256 512; do
    rsvg-convert -w "$size" -h "$size" "$SVG" -o "$ICONSET/icon_${size}x${size}.png"
    rsvg-convert -w "$((size * 2))" -h "$((size * 2))" "$SVG" \
        -o "$ICONSET/icon_${size}x${size}@2x.png"
done
iconutil -c icns "$ICONSET" -o "$RES/MissionCentrePg.icns"

# ---- 3. Binary and gresource ------------------------------------------------
cp "$BINARY" "$MACOS_DIR/mission-centre-pg"
cp "$GRESOURCE" "$RES/mission-centre-pg.gresource"

# ---- 4. Dylibs --------------------------------------------------------------
dylibbundler -of -b -x "$MACOS_DIR/mission-centre-pg" \
    -d "$FRAMEWORKS" -p "@executable_path/../Frameworks" \
    -s "$GTK_PREFIX/lib" -s "$ADW_PREFIX/lib" -s "$BREW/lib"

# ---- 5a. Icon theme ---------------------------------------------------------
cp -R "$ICON_PREFIX/share/icons/Adwaita" "$RES/share/icons/"
cp -R "$HICOLOR_PREFIX/share/icons/hicolor" "$RES/share/icons/"
gtk4-update-icon-cache -q -t -f "$RES/share/icons/Adwaita"

# ---- 5b. Pixbuf loaders -----------------------------------------------------
# The loaders are Mach-O objects linking the bundled dylibs, so they need
# relocating too -- copying them alone leaves them pointing at Homebrew.
cp "$PIXBUF_PREFIX"/lib/gdk-pixbuf-2.0/2.10.0/loaders/*.so "$LOADER_DIR/" 2>/dev/null || true
cp "$RSVG_PREFIX"/lib/gdk-pixbuf-2.0/2.10.0/loaders/*.so "$LOADER_DIR/"

for loader in "$LOADER_DIR"/*.so; do
    dylibbundler -of -b -x "$loader" -d "$FRAMEWORKS" \
        -p "@executable_path/../Frameworks" -s "$BREW/lib"
done

GDK_PIXBUF_MODULEDIR="$LOADER_DIR" gdk-pixbuf-query-loaders > "$PIXBUF_DIR/loaders.cache"

# gdk-pixbuf-query-loaders writes absolute paths; rewrite them relative to the
# cache file's own directory so the bundle survives being moved.
sed -i '' "s|\"$LOADER_DIR/|\"loaders/|g" "$PIXBUF_DIR/loaders.cache"

# ---- 5c. Schemas ------------------------------------------------------------
# All three are needed: libadwaita reads GTK's schemas at startup and aborts
# if they are absent.
SCHEMA_SRC="$BUILD_ROOT/macos-schemas"
rm -rf "$SCHEMA_SRC"
mkdir -p "$SCHEMA_SRC"
cp "$SOURCE_ROOT/data/$APP_ID.gschema.xml" "$SCHEMA_SRC/"
cp "$GTK_PREFIX"/share/glib-2.0/schemas/*.xml "$SCHEMA_SRC/"
cp "$ADW_PREFIX"/share/glib-2.0/schemas/*.xml "$SCHEMA_SRC/"
glib-compile-schemas --strict "$SCHEMA_SRC" --targetdir "$RES/glib-2.0/schemas"

# ---- 6. Sign, inner-out -----------------------------------------------------
# Not --deep, which is deprecated and signs in the wrong order.
find "$FRAMEWORKS" "$LOADER_DIR" -type f \( -name '*.dylib' -o -name '*.so' \) \
    -exec codesign --force --sign - {} +
codesign --force --sign - "$APP"

# ---- 7. Relocatability sweep ------------------------------------------------
leaked="$(find "$CONTENTS" -type f \( -name '*.dylib' -o -name '*.so' -o -perm -u+x \) -print0 \
    | xargs -0 otool -L 2>/dev/null | grep -F "$BREW/" || true)"
if [ -n "$leaked" ]; then
    echo "bundle still references Homebrew:" >&2
    echo "$leaked" >&2
    exit 1
fi

echo "built $APP"
```

# Mission Centre PostgreSQL on macOS

A native macOS build, delivered as a double-clickable `MissionCentrePg.app`.

Targets **Apple Silicon** and **macOS 15 or later**. Intel is out of scope: Homebrew ships
per-architecture bottles, so a universal build would mean building the whole GTK stack twice.

## Prerequisites

Rust via [rustup](https://rustup.rs), not Homebrew. Everything else via
[Homebrew](https://brew.sh):

    brew install meson ninja pkg-config gtk4 libadwaita adwaita-icon-theme \
                 blueprint-compiler gettext librsvg dylibbundler

`iconutil` and `sips` ship with macOS. `glib-compile-schemas`,
`gdk-pixbuf-query-loaders` and `gtk4-update-icon-cache` arrive as gtk4 dependencies.

## Building

    export PKG_CONFIG_PATH="$(brew --prefix)/lib/pkgconfig:$PKG_CONFIG_PATH"
    export BUILD_ROOT="$PWD/build-macos"
    meson setup "$BUILD_ROOT"
    ninja -C "$BUILD_ROOT"

If `meson setup` cannot find `gtk4` or `libadwaita-1`, Homebrew's pkg-config path is not
wired into your shell — export `PKG_CONFIG_PATH` as above and retry.

## Running from the build directory

    codesign --force --sign - "$BUILD_ROOT/src/mission-centre-pg"
    glib-compile-schemas --strict data --targetdir "$BUILD_ROOT/data"
    export MCPG_RESOURCE_DIR="$BUILD_ROOT/resources"
    export GSETTINGS_SCHEMA_DIR="$BUILD_ROOT/data"
    "$BUILD_ROOT/src/mission-centre-pg"

The `codesign` step is not optional — see the keychain quirk below.

## Building the app bundle

    ninja -C "$BUILD_ROOT" bundle
    open "$BUILD_ROOT/MissionCentrePg.app"

This produces a relocatable bundle: the GTK stack, adwaita-icon-theme, the pixbuf loaders
and the compiled GSettings schemas all live inside `Contents`. The script fails the build
if any bundled object still references `/opt/homebrew`.

To prove self-containment properly:

    brew unlink gtk4 libadwaita adwaita-icon-theme librsvg
    open "$BUILD_ROOT/MissionCentrePg.app"
    brew link gtk4 libadwaita adwaita-icon-theme librsvg

## Platform support

| Platform | Status |
|---|---|
| macOS 15+, Apple Silicon | Supported |
| macOS, Intel | Out of scope |
| Linux | Full support (the original platform) |

Nothing is stubbed on macOS. The application's only data source is a PostgreSQL server over
TCP, which behaves identically on every platform, so there is no macOS-specific data path to
implement or degrade.

## Known macOS quirks

* **The keychain re-prompts after every rebuild.** The bundle is ad-hoc signed, and an
  ad-hoc signature has no stable identity, so its designated requirement changes on each
  rebuild. macOS therefore treats each build as a different application and "Always Allow"
  does not stick. Only a Developer ID signature fixes this, which is out of scope.
* **An unsigned binary cannot reach the keychain at all.** Running straight from
  `build-macos/src/` without `codesign --force --sign -` fails with
  `errSecMissingEntitlement` (`-34018`). This looks like a credentials bug and is not one.
* **Gatekeeper warns on any Mac other than the one that built the bundle**, for the same
  ad-hoc-signature reason.
* **Distribution is not supported.** No Developer ID signing, notarisation or DMG. The
  bundle is for your own machines.

## Integration tests

The container-backed tests need a Docker-compatible runtime; see `docs/development.md`.

## Notes for the implementer

**One refinement over the spec.** Spec §3.2 lists four bundle paths; Task 2 defines five. `GDK_PIXBUF_MODULEDIR` was added alongside `GDK_PIXBUF_MODULE_FILE` as belt-and-braces: the relative-path rewrite in Task 6 §5b is the mechanism gtk-mac-bundler and MSYS2 both rely on, but setting the module directory explicitly as well means loader resolution does not rest solely on that rewrite behaving as expected. Task 7 Step 2 is where this gets confirmed.

**Where this is most likely to go wrong.** Blank icons after Task 6 — the `loaders.cache` path rewrite. Task 7 Step 2 tells you how to read the cache and confirm. Everything else in the port either works or fails loudly.
